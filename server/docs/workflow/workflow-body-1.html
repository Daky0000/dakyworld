Section 00

How to read this

Every step below answers the same six questions in the same order. If a step cannot answer all six it is not a step — it is a wish, and it does not belong in a workflow.

FieldWhat it means, and why it is there
Starts whenThe exact trigger. A clock tick, a status change, an inbound event, or a person pressing something. A step with no trigger never runs; a step with two triggers runs twice.
DoesThe work itself, in one or two sentences. Written so that somebody reading only this column can tell whether it happened.
ToolsThe exact catalogue keys called. These are real: they match server/src/services/tools/catalogue.ts, and an agent that has not been granted one cannot run the step.
GateWhat has to be true for the step to take effect rather than merely be prepared. This is the autonomy level, the dry-run flag, and any spend ceiling.
Ends whenThe state change that proves it finished. Almost always a status moving, a record being written, or a document existing.
Stops and asks ifThe conditions under which the agent must not proceed. This column is the reason the rest of the document is safe.

The three kinds of step

Automatic — the clock or an event fires it. Nobody asks. Agent — an agent does the work, within its gate. Decision — a person decides. The agent prepares and waits.

Nothing in this document is live until you raise it

Every agent ships at autonomy 1 with dry run on. At that setting each step below still runs, still reads the record, still produces its output — and stops before the output reaches a client, a card or a live system, showing you what it would have done instead. That is not a limitation to be worked around; it is how the workflow is meant to be commissioned. Section 12 sets out the order to lift it in.

Section 01

The rules that govern every step

Five rules apply to all twenty-seven agents and all thirty-nine tools. They are enforced in one place — services/tools/invoke.ts — rather than repeated in each tool, which is what makes a new tool safe on the day it is added.

Rule 1 · The autonomy ladder

0ObserveReads and reports. Takes no action of any kind.
1DraftPrepares work. Nothing leaves the building. Every agent seeds here.
2RecommendChooses an action and explains why. A person decides.
3ExecuteActs outside the company without asking — an email leaves, a meeting is booked, an issue is opened. The threshold for every outward-facing tool.
4AutonomousSpends money. Runs whole routine workflows; only escalations reach you. The threshold for every tool that charges.
5DelegatedMaterial financial and legal authority. Not settable from the app at all — it needs a recorded owner decision first, and the API refuses it.

Rule 2 · The four gates, in order

Every tool call passes through the same four checks before the handler runs. A call that fails any of them is refused and recorded — the refusals are what answer “why did nothing happen last night”.

#GateRefuses when
1ReadinessThe integration behind the tool has no credential. The refusal names the exact settings tab to paste it into.
2GrantThe agent’s toolkit does not include this key. An agent with an empty toolkit can call nothing at all.
3AutonomyThe tool is outward-facing and the agent is below level 3, or it spends and the agent is below level 4. This does not error — it downgrades the call to a preview, because a prepared action a person can approve is the useful outcome.
4SchemaThe arguments are not the declared shape. A model will confidently pass a string where a date was wanted; this catches it before the handler does something strange with it.

Rule 3 · Dry run is a floor, not a default

An agent’s dryRun flag sits above its autonomy level. When it is on, every write, every outward action and every spend is prepared and stopped — and an owner asking for a real run from the call site cannot switch it off. Turning dry run off is a deliberate act on that agent’s own card, and it is the single most consequential control in the system.

Rule 4 · Everything is written down

Every call lands in ToolCall: which agent, which tool, the arguments, the result, whether it was a dry run, what it cost, how long it took, and — for a refusal — the reason. Nothing an agent does is invisible, including the things it was stopped from doing.

Rule 5 · Money is named

A tool that can spend is flagged as such in the catalogue, and that flag is not decoration: it raises the autonomy threshold to 4, records the cost against the call, and is checked against the ceiling in agents.maxCallUsd. Four tools spend today.

The one thing that is never delegated

No agent can grant a permission — not to itself, not to another agent. AI People Operations can recommend that a toolkit be widened or narrowed and must escalate it; it cannot act on its own recommendation. The grant model has exactly one writer, and it is you.

Section 02

The clock

Five jobs run without anyone asking. They tick once a minute, are settled independently — lead capture failing must not stop an invoice going out — and each advances its own next-due marker before starting work, so a crash cannot be retried in a loop and a restart cannot fire the same slot twice.

JobFiresWhat it does, and its safety rail
Lead capture Per source, at its own local times Starts any scraper source whose next run is due. A slot missed by more than six hours is skipped rather than stampeded through on boot. Refuses if the monthly budget or the concurrency limit is reached.
Care plan billing 06:00 local, on each plan’s billing day Raises the retainer invoice. At most three missed months are billed after an outage. A duplicate is a database error, not a duplicate.
Scheduled email Every minute Sends anything whose scheduled time has passed, up to 25 per tick. Suppression is re-checked immediately before the socket opens.
Sequences Every minute Sends the next due step of every active enrolment, inside that sequence’s send window only.
Housekeeping Every minute Resumes interrupted capture runs and prunes run history past its retention window.

Why in-process rather than a cron container

Dakyworld OS runs as a single Railway service. One interval inside it has no moving parts to keep in step with a deploy — no second image, no second set of environment variables, and no way for the schedule to be running a version of the code the app is not.
