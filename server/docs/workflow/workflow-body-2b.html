Section 05

How an agent actually runs

Every stage in this document is carried out by the same machine. A task is created, an agent claims it, a loop turns, and the task ends in one of five states — each of which means something different and needs something different from you.

The life of one task

#What happensDetail
1A task is created By you, by the clock, by an event, or by a manager agent handing work to one of its reports. It names the agent, the brief, and the record it is about.
2A runner claims it The claim is a conditional write, so two runners reaching for the same task cannot both get it. Only agents set to Active are picked up — a queue can be filled before its agent is switched on.
3It is told who it is Its ten prompt layers, its skills, the company's own details, and what it already concluded about this subject — see the memory band below.
4It is told what this is The record resolved in full: the lead's score, status, contact details and discovery notes; the invoice's age and amount; the project's open tasks. It fetches anything further with a tool, which is what makes a fact citable.
5It is handed its tools Only what its toolkit grants, plus escalate, remember and — for a manager — delegate.
6The loop turns It calls a tool, reads the answer, decides again. Every call goes through the same four gates as before; the timeline is written as it happens, so a task that is still running shows what it has done so far.
7It ends In one of the five states below, with a summary in its own words: what it did, what it found, what a person should do next.

The five ways a task ends

StateWhat it meansWhat you do
Done It finished, and everything it did took effect. Nothing. Read the summary if you want to.
Ready to approve It finished, and some or all of the work was prepared rather than carried out — the agent is in dry run, or below the autonomy those tools need. Read the timeline: the prepared steps say exactly what would have happened. Approve it, or raise the agent's autonomy to stop being asked.
Stopped and asked It hit one of the conditions in Section 11 and used escalate rather than guessing. Answer the question in the drawer. The answer is appended to the brief and it carries on from there.
Failed Something broke — no API key, a model error, a tool that threw. The reason is on the task. A rate limit re-queues itself; everything else waits for you.
Cancelled You stopped it before it started. Nothing. A task mid-run cannot be cancelled — the loop is not interruptible, and a status that claimed otherwise would be a lie.

“Ready to approve” is the point of autonomy level 1, not a failure of it

An agent at level 1 with dry run on still does the whole job — it reads the records, works out what should happen, and prepares every action. What it does not do is let any of it take effect. So the normal outcome at the shipped settings is one thing to approve rather than five things to do, and the timeline tells you precisely what each prepared step would have done. That is why the commissioning order in Section 12 starts where it does.

What an agent remembers

Every agent's prompt has always ended with the rule — retain decisions, their reasons and their outcomes; never retain secrets. There was nowhere to put them, so every task started from nothing and an agent could reach the same wrong conclusion about the same lead every morning without noticing it had been there before. Now it keeps them, and is handed them back.

KindWhat goes in it
DecisionA choice it made, and why. “Wrote about the missing website rather than the slow checkout — the audit found no site at all, which is the stronger opening.”
OutcomeWhat came of it. The half that makes a decision worth keeping.
FactSomething it learnt about a lead, a client or the business.
LessonA general conclusion about its own work: “this approach does not land on this segment”.
PreferenceSomething you told it to do differently. You can write one directly from its drawer.

Recall is by subject, not by similarity. A memory is filed against the thing it is about — a lead, a client, or self for a standing lesson — and an agent picking up a task about a lead is handed what it concluded about that lead, plus its own standing lessons, and nothing about anybody else. A search across everything would occasionally surface a fact about a different client in the context of this one, and the failure mode of that is a letter to the wrong company containing the right facts.

A memory is never allowed to hold a credential

Not because an agent would not be told — every prompt says so — but because a memory is a durable record that is re-read into a prompt every time its subject comes up. A token written into one is a token re-read every morning for a year. So the store refuses anything credential-shaped outright: known key formats, private keys, and the sentence somebody writes when they are about to hand one over. It is deliberately eager, because refusing a memory costs a rephrase and accepting one costs far more.

Delegation runs down the chart only

A manager may hand work to one of its own direct reports — never sideways, never upward. The child task carries the same record and the same priority, and the manager does not wait for it: it carries on with its own part, and the two show up on the same board. An agent routing work around the person who owns a lane is the failure this prevents, and the rule is enforced in code rather than asked for in a prompt.
