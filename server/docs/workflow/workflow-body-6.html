Section 12

Commissioning it

Everything above is built and every agent is at level 1 with dry run on. That is the correct starting position, not a limitation — the sensible order is to lift the gate where the cost of being wrong is lowest, watch the audit trail, and only then move up.

PhaseRaiseToWatch for a week
1 Business Intelligence, Finance Controller, Risk & QA, Board Chair, CEO Level 2, dry run on Nothing can go wrong: every tool they hold is read-only. This is where you find out whether the reports are worth reading.
2 Lead Lifecycle Manager, SEO Specialist, QA Tester Level 2, dry run off Lead statuses start moving on their own. Check a day of them against what you would have decided.
3 The studio — Graphic Designer, Video Editor, Ad Designer, Copywriter, Web Developer Level 2, dry run off Briefs, plans and pages arriving. None of it reaches a client; all of it is judged on whether a person would use it as-is.
4 Outbound Communications, Client Communications, Support Desk Level 3 Email starts leaving the building. Start with one sequence, on a filter you would defend, to fewer than twenty people.
5 Delivery Director, Automation Engineer, Commercial Operations Level 3 Tasks assigning themselves and proposals drafting themselves. Invoices still stop at DRAFT — that never changes.
6 Lead Lifecycle Manager only Level 4 Money. Capture runs start on their own schedule against the budget ceiling. Check the spend daily for the first week.

The two numbers to keep on the Agents screen

“Can act unattended” counts the agents above level 2 or with dry run off. It should only ever go up because you decided it should. Tool spend, last thirty days is on the Tools screen: every call that cost money, with the agent that made it. If either surprises you, the audit trail has the answer, because every call is in it.

Adding a tool

Two ways, and they are deliberately different. In code — one entry in the catalogue, which inherits the permission model, the audit trail and both screens by existing. By connection — an MCP server, whose tools join the same catalogue as mcp.<server>.<tool> and pass every gate above on identical terms. What a tool does stays reviewable in a diff; which servers are trusted, and how far, is yours to set.
