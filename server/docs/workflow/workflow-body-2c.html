Stage 1 · Acquisition

Getting a business into the pipeline

Three doors, and only one of them is a person typing. Everything that arrives is scored, de-duplicated against everything already known, and filed with the run that found it — so “where did this lead come from” is answerable a year later.

Door A — Scheduled capture

1.A.1

A capture source comes due

Clock
Starts when
The minute tick finds a source whose nextRunAt has passed. Each source carries its own local times and timezone.
Does
Advances nextRunAt first, then starts the run. A slot missed by more than six hours is skipped rather than replayed — coming back from an outage should not mean six hours of scrapes firing at once.
Tools
scheduler — not an agent action
Gate
Refused outright if the month’s Apify spend is at the budget ceiling, or the concurrent-run limit is reached. Neither is negotiable by an agent.
Ends when
A ScraperRun row exists with a run id from Apify.
Stops and asks if
No Apify token is connected, or the budget is exhausted. The run is not attempted and the reason is recorded.
1.A.2

Price it before it runs

Lead Lifecycle Manager
Starts when
A capture is being planned, by hand or by an agent.
Does
Reads the actor’s published rates from Apify at run time and turns the input into a count of billable events. A hard ceiling is derived for any pay-per-event run that has not been capped by hand.
Tools
capture.costcapture.plancapture.spend
Gate
capture.plan asks Claude and therefore spends; level 4 to run it for real, otherwise it is priced and shown.
Ends when
An estimate exists, with the ceiling that will be enforced.
Stops and asks if
The estimate exceeds the per-run ceiling. Never re-priced from memory: actor rates change, and a stale number in a spending guard fails silently.
1.A.3

Run the capture

Lead Lifecycle Manager
Starts when
1.A.1 fires, or a person presses Run, or an agent at level 4 decides to.
Does
Executes the actor, normalises each row, builds a de-duplication key, scores it, and writes the ones that are new.
Tools
capture.run
Gate
Level 4. This is the tool that spends real money on every call, and the only one an operational agent holds.
Ends when
The run records its tally: fetched, created, skipped as duplicates, filtered below the score floor.
Stops and asks if
The run would exceed its derived charge ceiling, or another run is already in flight for the same source.
1.A.4

Score and file

Automatic
Starts when
Each row of a run is normalised.
Does
Scores 0–100 from what is actually known: a contact email is worth the most, then a phone number, then a website — and a business on a free page-builder domain scores higher than one on a proper domain, because it is the strongest buying signal Dakyworld has. Review count and rating add credibility; a business with neither address nor city loses nothing but gains nothing.
Tools
scoring — part of the run
Gate
None. Scoring reads and writes nothing outside the lead itself.
Ends when
The lead exists at status NEW with a score, a source, and the run that found it.
Stops and asks if
Below the source’s score floor it is not created at all. A run that creates nothing is a run whose floor is too high for the segment — the report says so rather than reporting failure.

Door B — The website form

1.B.1

An enquiry arrives

Integration Architect
Starts when
A signed POST lands on the webhook endpoint from the contact form on dakyworld.com, a Typeform, or a Zap.
Does
Records the raw payload first, then reads the fields whatever the sender decided to call them — name, full_name and Your Name are all the same field, and rejecting an enquiry over a field name loses a real customer. Creates a scored lead, de-duplicated against everything the scrapers have already found.
Tools
webhooks.readwebhook.dispatch
Gate
Intake is not an agent action and needs no autonomy. Dispatching an event outward is, and needs level 3.
Ends when
A lead exists at NEW, and the event is marked handled with the lead id.
Stops and asks if
The signature does not match: the event is still recorded, flagged unverified, and not acted on. A run of these is either a misconfigured sender or somebody probing.

Door C — A spreadsheet

1.C.1

Import a list

You
Starts when
A workbook is uploaded or picked out of Google Drive.
Does
Claude reads the grids, proposes which table is the data and what each column means, and shows a preview. You correct the plan; the commit writes the leads.
Tools
imports — Owner-only, not agent-callable
Gate
A person, always. No agent can import a list — the blast radius of a mis-mapped column across 3,000 rows is too large to delegate.
Ends when
The batch exists as a LeadGroup, and every lead carries the import it came from.
Stops and asks if
Always. The plan is never committed without being looked at.

What all three doors share

Whichever door a business comes through, it lands as a NEW lead with a score, a de-duplication key, and a traceable origin — and it immediately becomes eligible for any active sequence whose trigger is LEAD_CREATED and whose filter it matches. That single fact is what makes Stage 3 automatic rather than remembered.

Stage 2 · Qualification

Deciding who is worth writing to

A score says how reachable a business is. It does not say whether they need anything. That is what the audit is for — and it is also what makes the first email specific rather than a mail merge, because every claim in it traces to something the audit actually observed.

2.1

Audit the business

Lead Lifecycle Manager
Starts when
A lead reaches NEW with a website or a domain to look at.
Does
A live check of the site and the domain: TLS and certificate validity, whether the site is served over plain HTTP, mail authentication (SPF, DKIM, DMARC), DNS, CMS version and exposed platform detail, mobile usability, and whether the business is running on a free mailbox.
Tools
company.auditsecurity.scanlead.read
Gate
Read-only. Runs at any level, including 0.
Ends when
Findings exist, each with the evidence behind it.
Stops and asks if
Nothing. An audit that finds little is a result — it means write a shorter email, not invent a longer one.
2.2

Qualify or disqualify

Lead Lifecycle Manager
Starts when
The audit returns.
Does
Moves the lead to QUALIFYING, then to QUALIFIED when there is an identifiable technology problem Dakyworld sells the fix for, or DISQUALIFIED when there is not. Writes why, in one line, either way.
Tools
lead.updatelead.read
Gate
A write to a lead. Below level 3 with dry run on it proposes the change and shows the reason; the status does not move until somebody agrees.
Ends when
LeadStatus is QUALIFIED or DISQUALIFIED, with a recorded reason.
Stops and asks if
The evidence contradicts itself, or the only reason to qualify is the score. A high score with no findings is a reachable business with no problem to solve.
2.3

Is this worth doing at all?

Sales Director
Starts when
A batch of leads reaches QUALIFIED.
Does
Ranks them by the evidence rather than the score, and recommends the smallest credible next step for each — which is almost always the thirty-minute consultation, not a proposal.
Tools
crm.readlead.readcalendar.read
Gate
Read-only; the output is a recommendation whatever the level.
Ends when
Each opportunity has a named next step, an owner and a date.
Stops and asks if
Anything reputationally risky, or a business whose pain is real but outside what Dakyworld sells — no on-site work, no hardware, no office networking, ever.
